## 언제 쓰는가

- 은행 잔액 조회, 증권 API, 카드 명세서 이메일
- Gmail 앱 비밀번호, VestMail/파일 암호
- API 키 발급·등록, OAuth, 권한/스코프
- 로그인·2차 인증·계정 설정
- "현실적인 문제" 때문에 막혔을 때

## 원칙

1. **비밀값은 채팅에 쓰지 않는다.** 비밀번호·앱키·시크릿·토큰을 요구하거나 출력하지 않는다
2. **AI는 절차·검증·오류 분석까지**, **사람은 신원 확인·동의·비밀값 입력**을 한다
3. **비밀값은 환경변수/시크릿 파일**로만 전달한다. 로그는 마스킹한다
4. **한 번에 한 단계** 진행한다. 성공 증거를 확인한 뒤 다음 단계로 간다
5. **재시도 제한** — 인증 실패는 2회까지. 그 이상은 사람에게 넘긴다
6. **권한 최소화** — 필요한 스코프만 요청한다

## 시스템별 체크

### 은행·증권 API
- 계좌번호·상품코드·앱키/시크릿을 구분한다
- 실전/모의 도메인을 혼동하지 않는다
- 키는 DB/시크릿에 암호화 저장한다
- 연결 테스트와 잔액 조회를 분리한다

### 이메일·명세서
- 앱 비밀번호는 계정 비밀번호와 다르다
- IMAP 활성화/2차 인증을 확인한다
- 첨부 파일은 매직바이트로 실제 형식을 확인한다
- 암호화 파일은 사용자가 입력한 비밀번호로만 연다

### 파일 암호·키
- 비밀번호를 커맨드라인 인자로 넘기지 않는다(환경변수/표준입력)
- 복호화 실패를 무한 재시도하지 않는다
- 임시 파일은 작업 후 삭제한다

### 로그인·권한
- 최소 권한/스코프
- 토큰 만료·갱신 경로
- 로그에 토큰/쿠키를 남기지 않는다

## 출력

1. **사람이 준비할 것** — 체크리스트
2. **AI가 실행할 검증** — 명령과 기대 결과
3. **성공 판정 기준**
4. **실패 시 진단 순서**
5. **비밀값 처리 방법** — 어디에 넣고 어디에 남기지 않는지
6. **롤백/해제**
