AssetFlow의 5개 역할 파이프라인을 순서대로 실행한다.

**요구사항:** $ARGUMENTS

## 규칙

- 각 단계는 `task` 도구로 해당 서브에이전트를 호출해 실행한다
- **앞 단계의 출력 원문을 다음 단계의 프롬프트에 그대로 넣는다.** 요약하지 말고 통째로 넘긴다
  - 특히 developer에게는 analyst의 AC와 architect의 설계를 **둘 다** 넘긴다
- reviewer와 tester에게 **개발자의 설명을 넘기지 마라.** `git diff` 로 스스로 보게 한다.
  이게 이 파이프라인의 존재 이유다
- 각 단계 출력을 사용자에게 그대로 보여준다. 생략하지 마라
- 단계가 실패하면(AC 없음, Blocker 있음) 다음으로 넘어가지 말고 멈추고 사용자에게 보고한다

## 순서

1. **analyst** — AC 와 영향 범위 확보
2. **architect** — 파일 목록·계약 변경표·구현 순서. AC 없으면 여기서 되묻는다
3. **developer** — 설계대로 구현하고 검증 명령을 직접 돌린다
4. **reviewer** — `git diff` 만 보고 리뷰. Blocker 있으면 여기서 멈춘다
5. **tester** — 명령을 실제로 돌려 Go/No-Go

## 완료 후

- **커밋하지 않는다.** `git status` 로 남은 것을 보여주고 멈춘다
  (`CONTRIBUTING.md` 는 `feature/*` 브랜치를 요구하므로 현재 브랜치도 확인해 보고한다)
- 무엇을 남겼는지, 무엇을 검증했고 무엇을 안 했는지 구분해 보고한다
- `.ai/session-log.md` 맨 위에 항목 추가를 **제안한다.** 기록 규약은 §32 다
