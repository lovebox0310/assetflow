## 현금은 3계좌다 (§28.7)

현금을 합쳐서 "현금 1개"로 보면 안 됩니다. 계좌마다 쓸 수 있는 성격이 다릅니다.

| 계좌 | 금액 | 성격 | 비상금 분자 |
|---|---|---|---|
| 투자금 | 38,000,000원 | 순수 사용가능 | **포함** |
| 자동이체 | 12,400,000원 | 고정지출 배정분, 월중 소진 | 제외 |
| 부가가치세 | 28,500,000원 | 세금 적립 보관, Filing 대기 | 제외 |

총 현금 78,900,000원 중 **48.2%만 지금 쓸 수 있습니다.** 이게 대시보드의 핵심 숫자입니다.

비상금 유지 개월은 투자금만으로 계산합니다. 총 현금을 분자에 넣으면 쓸 수 없는 돈으로
유지 개월이 부풀려집니다. 자동이체 잔액을 더하면 분모(월 필수지출)와 이중 계상됩니다.

## 부가가치세 계산 (§28.7)

### 실제 신고 값

| 필드 | 값 | 출처 |
|---|---|---|
| `grossSales` (월 공급대가) | 9,020,000원 | 세금계산서 발행액 |
| `purchaseTax` (월 매입세액) | 320,000원 | 실제 인정분 |
| `cardSupplyAmount` (월 카드매출) | 5,000,000원 | 월 평균 |
| `monthlyAccrual` (월 적립) | 820,000원 | 현행 운영 |

`hasActualFilingData: true` — 계획 기준이 아니라 실제 산식으로 계산합니다.

### 사업소득은 부가가치세 산정 기준이 아니다

**사업소득은 필요경비를 차감한 세후 순수익**이고, 부가가치세는 **공급대가(매출)** 에서 냅니다.

```
매출세액 = 공급대가 9,020,000 × 10/110 = 820,000원
```

현행 적립액 820,000원은 **결과만 우연히 일치**한 것입니다. 사용자는
"사업소득 8,200,000 × 10%"로 계산했지만, 실제로는 "공급대가 9,020,000 ÷ 11"입니다.
우연히 같은 값이 나온 이유는 두 계산이 모두 820,000을 냈기 때문입니다.

> `8,200,000 × 10/110`이었다면 745,455원입니다. 우연히 맞은 것이라
> 매출이 늘거나 사업소득과 공급대가가 어긋나면 틀어집니다. 적립 근거를
> **공급대가 기준**으로 바꿔 두는 것이 안전합니다.

다만 사업소득 8,200,000과 공급대가 9,020,000에서 지출 2,053,753원을 빼면
6,966,247원으로, 사업소득이 1,233,753원 큽니다. 아래 [어긋남](#사업소득과-공급대가가-어긋난다) 참고.

### 용어 정리

| 용어 | 뜻 |
|---|---|
| 공급가액 | 부가세 **제외** 매출 |
| 공급대가 | 부가세 **포함** 매출 |
| 매출세액 | 공급대가 × 10/110 |
| 매입세액 | 매입하면서 낸 세액 |

`10/110`은 **공급대가**에 곱해야 합니다. 공급가액에 10%를 다시 곱하면 이중 계상입니다.
`10/110` 자체가 틀린 방법은 아니고, 매입세액과 카드 발행세액공제를 빠뜨린 것이 문제입니다.

### 실제 산식

```
납부세액(공제 전) = 매출세액 − 매입세액
카드 발행세액공제  = 카드매출 공급대가 × 공제율   (연 한도, 납부세액 이내)
실제 납부세액      = 납부세액(공제 전) − 카드 발행세액공제
```

### 실제 산식 결과

```
매출세액       = 9,020,000 × 10/110        = 820,000원
매입세액                                −    320,000원
납부세액(공제 전)                          =   500,000원 (월)
카드 발행세액공제 (연)                    −    780,000원
실제 납부세액 (월 환산)                     =   435,000원
```

### 카드 발행세액공제 (부가가치세법 제46조)

| 항목 | 내용 |
|---|---|
| 업종 | 컴퓨터수리업 → 음식점·숙박업 아님, **1.3%** 적용 |
| 대상 | 개인사업자, 직전연도 공급가액 10억원 이하 (법인 제외) |
| 기준 | **카드·현금영수증으로 받은 매출**의 공급대가 |
| 공제율 | 1.3% (2026년 말까지) / 음식점·숙박업 등 2.6% |
| 한도 | 연 1,000만원 (2026년 말까지) |
| 환급 | **불가**. 납부세액을 0원으로 만드는 범위까지만 |

> 카드매출 5,000,000원 × 12 = 60,000,000원 × 1.3% = **780,000원**.
> 연 한도 1,000만원에 크게 미달하고 연 납부세액 6,000,000원에도 미달하므로
> 어느 쪽에도 걸리지 않습니다.

> 공제율과 한도는 세법 개정으로 바뀝니다. 코드에서는 `taxPolicy` 객체로 분리해
> 상수로 박지 않았습니다. 2026 세제개편안에 따라 2027년부터 1.2%·연 500만원으로
> 변경될 예정이며 확정 여부는 확인이 필요합니다.

### 신고는 반기 단위다

12분의 1이 아니라 **반기(6개월) 단위**로 고지합니다.

| | 산식 | 금액 | 시점 |
|---|---|---|---|
| 1기 = 1~6월 실적 | | | |
| 1기 예정고지 | 직전 반기 실제 납부세액 × 1/3 | 870,000원 | 4월 |
| 1기 확정고지 | 1기 실제 − 예정고지 | 1,740,000원 | 7월 |
| 2기 = 7~12월 실적 | | | |
| 2기 예정고지 | 직전 반기 실제 납부세액 × 1/3 | 870,000원 | 10월 |
| 2기 확정고지 | 2기 실제 − 예정고지 | 1,740,000원 | 1월 |

연 4회 합계 5,220,000원 = 실제 납부세액과 일치합니다.

### 적립액이 실제 납부보다 많다

| | 월 | 연간 |
|---|---|---|
| 적립액 (매출세액 기준) | 820,000원 | 9,840,000원 |
| 실제 납부 | **435,000원** | **5,220,000원** |
| 차액 | 385,000원 | **4,620,000원** |

적립액이 **매출세액(=820,000원)** 기준이라 매입세액 320,000원과 카드공제 780,000원을
반영하지 않습니다. 결과적으로 1년간 **4,620,000원**이 쌓이고, 적립액의 47.0%입니다.

> Filing 후 이체 대상은 카드 발행세액공제분 780,000원이 아니라
> **4,620,000원**입니다. 앞에서 780,000원만 이체한다고 안내한 것은 잘못이었습니다.

선택지는 두 가지입니다.

1. **그대로 두기** — 매달 385,000원이 쌓이고 Filing 후 전액 이체한다.
   현금 흐름 예측이 쉽지만 세금 계좌가 불필요하게 팽창합니다.
2. **적립액을 실제 납부세액(435,000원)으로 낮추기** — 고지 직전에만 금액이 모입니다.
   이 경우 `monthlyAccrual`을 435,000원으로 바꾸고 잔액은 0원이 됩니다.


자동 이체는 한국투자증권 API와 이체 권한이 필요해 현재 MVP 범위 밖입니다.

## 알아둘 점

- **월 필수지출 단일 출처**: 지출 내역 합계(2,053,753원) 하나만 씁니다.
  대시보드 분모와 `settings.html` 초기값이 같은 값을 읽습니다 (§28.7).
- **종합소득세는 미확정**: 보통 0원이나 납부되는 달이 있습니다. `notIncluded`에
  `amount: null`로 남겨 두었고, UI는 **"세금 미반영"** 경고를 표시합니다.
  0원을 넣어 지표를 조작하지 않습니다.
- **세금 계좌는 한투 발행어음 CMA**: 은행 예금이 아니라 증권사 발행어음 상품입니다.
  이자는 발생하나 Filing 전에는 인출하지 않습니다. 사용자는 순수 현금보다
  **'기타 자산'**으로 보는 운영 관점을 우선하므로 그 관점에 맞춰 표기합니다 (§28.7).
- **Filing 후 잔액 이체**: 잔액은 카드 발행세액공제분이 아니라
  **적립액과 실제 납부세액의 차액 4,620,000원(연)** 입니다.
  이 이체는 사용자가 수동으로 해온 일이며, 자동화 여부는 미결입니다.
  자동화는 한국투자증권 API와 세금 일정, 이체 권한이 연결돼야 하므로 MVP 밖입니다.
- **카드결제금액 5,000,000원의 의미**: 카드 발행세액공제는 **매출**이 받은 금액을
  기준으로 합니다. 사용자가 카드%로 *지출*한 금액이라면 이 공제와 무관하고
  매입세액(세금계산서) 대상이 됩니다. 매출 기준임을 전제로 계산했습니다.

## 제약

- **하드코딩 색상 금지** (§28.4). 원시 값은 `tokens.css`의 `:root`에만 있고 나머지는 `var()`만 씁니다.
- **다크 모드 없음** (§28.4). MVP 제외. 추가 시 `theme.darkAlgorithm` 한 줄이면 충분합니다.
