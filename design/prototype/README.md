- 목표: 와이어프레임 합의 → 확정 디자인을 React + antd 6 + Apache ECharts로 이관

## 데이터 규칙

`mock-data.js`의 값은 `project.md` §23 "표시 규칙" 공식을 그대로 적용한 결과입니다.

| 카드 | 공식 | 값 |
|---|---|---|
| 순자산 | 총자산 − 총부채 | 416,100,000 − 62,500,000 = **353,600,000원** (축약 3.5억) |
| 월 수지 | 월 총수입 − 월 총지출 | 8,400,000 − 7,160,000 = **+1,240,000원** |
| 비상금 유지 개월 | **투자금** ÷ 월 필수지출 | 38,000,000 ÷ 6,700,000 = **5.7개월** |
| 투자 가능 현금 | 투자금 잔액 | **38,000,000원** (현금의 48.2%) |
| 부가가치세 | 다음 Filing까지 남은 개월 | **1개월 후** (2기 예정, 2026년 10월 25일) |

축약 표기(`3.5억`)는 카드, 상세 표기(`353,600,000원`)는 상세 화면에 씁니다 (§28.3).
차트는 목업이므로 인라인 SVG이며, 실제 구현은 Apache ECharts로 교체합니다.

## 현금은 3계좌다 (§28.7)

현금을 합쳐서 "현금 1개"로 보면 안 됩니다. 계좌마다 쓸 수 있는 성격이 다릅니다.

| 계좌 | 금액 | 성격 | 비상금 분자 |
|---|---|---|---|
| 투자금 | 38,000,000원 | 순수 사용가능 | **포함** |
| 자동이체 | 12,400,000원 | 고정지출 배정분, 월중 소진 | 제외 |
| 부가가치세 | 28,500,000원 | 세금 적립 보관, Filing 대기 | 제외 |

총 현금 78,900,000원 중 **48.2%만 지금 쓸 수 있습니다.** 이게 대시보드의 핵심 숫자입니다.

비상금 유지 개월은 투자금만으로 계산합니다. 총 현금을 분자에 넣으면 쓸 수 없는 돈으로
유지 개월이 부풀려집니다. 자동이체 잔액을 더하면 분모(월 필수지출)와 이중 계상됩니다.

## 부가가치세는 10/110으로 계산하지 않는다 (§28.7)

`10/110`은 부가세 포함 매출에서 부가세만 뽑는 근사치입니다. 실제 신고는
**과세 매출세액 − 매입세액**입니다. 매입세액이 크면 근사가 실제 세금을 크게 과대 평가합니다.

목업 기준 비교:

| 기준 | 월 납부세액 | 연간 |
|---|---|---|
| 10/110 근사 (월 매출 14,000,000 ÷ 11) | 1,272,727원 | 15,272,727원 |
| 실제 산식 (매출세액 14,000,000 − 매입세액 3,200,000 = 10,800,000 ÷ 12) | **900,000원** | 10,800,000원 |

연간 4,472,727원을 과대 평가합니다. 현재 월 적립액 1,200,000원도 법정 고지세액
900,000원보다 300,000원 많으므로 과다 적립 중입니다.

Filing 일정은 확정신고 1/7월, 예정신고 4/10월입니다. Filing 후 세금 계좌 잔액 전액은
투자금으로 이체합니다. 이 과정을 목업에서는 수동으로 표현했습니다.

## 알아둘 점

- **월 필수지출 출처 불일치**: 대시보드 분모는 6,700,000원(자동이체 설정값)인데
  `settings.html` 초기값은 7,160,000원(월 총지출)입니다. §28.7에 "단일 출처" 규칙을
  넣었으므로 Issue 4에서 자동이체 설정값으로 통일해야 합니다. 목업 단계에서는
  두 값을 함께 두어 불일치를 드러내 두었습니다.
- **세금 계좌는 한투 발행어음 CMA**: 은행 예금이 아니라 증권사 발행어음 상품입니다.
  지급일 전까지 인출 가능하므로 현금성 자산에 포함하되, '기타 자산' 성격으로
  별도 표기합니다.§28.7
- **과다 적립 이체**: Filing 후 잔액을 투자금으로 옮기면 비상금이 5.7개월 → 9.9개월로
  늘어납니다. 이 이체는 사용자가 수동으로 해온 일이며, 자동화 여부는 미결입니다.
  자동화는 세금 일정과 계좌 이체 권한이 연결돼야 하므로 MVP 밖으로 보고했습니다.

## 제약

- **하드코딩 색상 금지** (§28.4). 원시 값은 `tokens.css`의 `:root`에만 있고 나머지는 `var()`만 씁니다.
- **다크 모드 없음** (§28.4). MVP 제외. 추가 시 `theme.darkAlgorithm` 한 줄이면 충분합니다.
- **접근성** (§28.5). WCAG 2.1 AA, 포커스 표시 유지, 폼 라벨은 `for`/`id`로 연결,
  오류는 `role="alert"`. 키보드만으로 전 기능 이동이 가능해야 합니다.
- **antd 미사용**. 이 단계는 레이아웃 합의가 목적입니다. 컴포넌트 구현은 Issue 3에서 합니다.
- `login.html` 폼은 실제 전송 없이 `dashboard.html`로 이동합니다. 인증은 Issue 2 범위입니다.
