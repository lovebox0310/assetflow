# 카드사 엑셀 샘플 보관소

카드매입 내역을 엑셀로 올리는 기능의 근거 자료다. 실제 명세서는 **가공하지 않은
상태로 커밋하면 안 된다.** 이 폴더에는 익명화한 사본만 둔다.

## 왜 규격이 먼저인가

이 프로젝트에서 카드 데이터의 목적은 하나다. **§28.7 매입 대조**다.

```
카드 엑셀 → 매입세액 합계 → VAT 신고서 purchaseTax(320,000원)와 대조
                              → 어긋나면 지출 목록이 불완전하다는 근거
```

그래서 카드 엑셀은 "총 결제금액" 하나만으로는 쓸 수 없다. **공급가액(부가세 제외)**
와 **세액**이 분리돼야 역산이 산다. 이 구분을 §28.7 "부가가치세는 공급대가에서
난다" 원칙과 동일하게 적용한다.

| 규격 필드 | 필수 | 쓰이는 곳 |
|---|---|---|
| `approvedAt` 승인일자 | 예 | 거래 월 배정 |
| `merchantName` 가맹점명 | 예 | 미분류 사업비용 성분 추정(자동 분류 금지) |
| `supplyExVat` 공급가액 | 예 | 매입 공급가액 역산 |
| `vat` 세액 | 예 | 인정 매입세액 |
| `grossAmount` 공급대가 | 예 | `supplyExVat + vat` 교차 검증 |
| `installmentCount` 할부 | 아니오 | 원금/이자 분리(미구현) |
| `approvalNo` 승인번호 | 아니오 | 중복 적재 방지 키 |
| `taxKind` 세액구분 | 아니오 | 영세/면세 제외 |
| `reversal` 취소구분 | 아니오 | 매입취소 차감 |

필수 컬럼 분해가 안 되는 카드사는 **미지원**으로 명시한다. 그 값을 임의로 나누면
매입 대조가 틀어지므로, 모르면 모른다고 남기는 편이 낫다.

## 구조

```
samples/card/
  README.md                 이 문서
  card-columns.json         컬럼 규격. FE/BE 공통 단일 출처
  anonymized/               커밋 가능한 익명화 샘플
  tools/
    inspect-xlsx.mjs        샘플을 조사하는 도구 (파서가 아니다)
```

## 카드사 샘플 추가 절차

1. **원본을 이 폴더에 두지 않는다.** 원본은 작업 폴더 등 로컬에만 둔다.
2. 아래 「익명화 체크리스트」를 모두 통과시킨다.
3. `anonymized/`에 `카드사-용도-기간.xlsx` 이름으로 넣는다.
   예: `삼성카드-매출내역-202609.xlsx`
4. 조사 도구를 돌려 헤더와 합계 행 패턴을 확인한다.
   ```
   node samples/card/tools/inspect-xlsx.mjs samples/card/anonymized/삼성카드-매출내역-202609.xlsx
   ```
5. `card-columns.json`의 `companies`에 카드사 프로파일을 추가한다.
   헤더 이름이 다르면 `headerAliases`에, 합계 행 표현이 다르면
   `rowRoles.grandTotal`에 **실제 문자열 그대로** 적는다.
6. 매핑이 안 되는 열이 있으면 추측해서 채우지 말고 그대로 남긴다.

## 익명화 체크리스트

커밋 전에 전부 확인한다. 하나라도 빠지면 커밋하지 않는다.

- [ ] 카드번호 전부 제거 (`1234-****-****-3456` 형태로 가린다)
- [ ] 회원명·생년월일·연락처 제거
- [ ] 가맹점명을 실제 상호로 두지 않는다 (`OO컴퓨터`처럼 가린다)
      - 단, 비용 성분 추정에 가맹점명이 쓰이므로 **형태는 유지**한다
        (길이, 한글/영문/숫자 혼합 여부)
- [ ] 승인번호 제거 또는 치환
- [ ] 지점명·지번 등 위치 정보 제거
- [ ] 파일 메타데이터(작성자, 경로) 제거
      - 엑셀은 문서 속성에 작성자명이 남는다. 저장 시 확인한다
- [ ] `외국계/캐피탈` 구역은 금액만 두고 가맹점명을 가린다

실제 금액이 그대로 남아 있으면 매입 대조 검증에 쓸 수 없으니, 합성 금액으로 바꾼다.
합성 샘플은 `synthetic-sample.xlsx`를 기준으로 삼는다.

## 파서는 두 벌, 규격은 하나

FE는 SheetJS로 **미리보기**, BE는 Apache POI로 **검증·저장**을 맡는다. 양쪽에
파서 규칙이 두 벌 생기므로 **판정 기준은 `card-columns.json` 한 곳에만 둔다.**

- FE: 원본 파일이 서버로 올라가지 않고 표를 먼저 보여준다
- BE: 정규화된 행만 받아 규격·검증식을 통과한 뒤 저장한다
- **사용자가 확인·승인하기 전에는 BE가 어떤 값도 확정하지 않는다**

규격(`card-columns.json`)을 고칠 때 FE 파서와 BE 파서를 **같은 PR에서 함께** 고친다.
한쪽만 고치면 미리보기와 실제 저장 결과가 어긋난다.

## 아직 정하지 않은 것

- 할부 결제를 현금흐름에 반영할 때 원금/이자 분리 규칙
- 경비율계산세액의 실제 지급세액과의 차이 처리
- 카드사별 파일 변경 이력(같은 카드사가 매달 헤더를 바꾸는지)
- .xls(구형) 지원 여부 — POI는 가능하지만 SheetJS는 별도 처리가 필요하다
